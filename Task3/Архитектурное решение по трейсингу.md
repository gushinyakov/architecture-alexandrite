# Архитектурное решение по трейсингу

### Мотивация

Поступают жалобы от пользователей на 
- медленную загрузку 
- потерю заказов

Трейсинг позволит прослежить цепочку запросов
- выявиться точечно места, которые испытывают нагрузку и тормозят всю цепочку
- найти условия, при которых заказ теряется (в сервисах или в шине) или возникают другие ошибки
- сократить время на исследование инцидентов

### Предлагаемое решение

[Диграмма решения](<Архитектурное решение по трейсингу.md>)

Для подключения трейсинга необходимо настроить

- Контейнер Jaeger (Jaeger server, jaeger db, jaeger ui)
- Подлкючить Open Telemetry SDK в микросервисы (Shop API, MES API, CRM API)

### Компромиссы

- Если для CRM и MES используются сторонние модули, могут возникнуть проблемы с внедрением в готовые корпоративные решения
- Создает дополнительную нагрузку и может негативно повлиять на скорость выполнения запросов.
Также необходимо выделить место на хранение трейсов.

Для решения этой пробелемы можно\
- отправлять только ошибочные спаны
- собирать определенный процент от всех спанов, чтобы сократить дублирование трейсов
- Уменить TTL для успешных трейсов

### Безопасность

- Внедрить авторизацию с доступом сотрудникам с ролями "Разработчик" и "Поддержка"
- Фильтрация чувствительных данных
удаление или маскировка персональных данных
исключение токенов, паролей
- Журналирование всех операций в сервисе по работе с трейсингом
- Доступ только под корпоративным VPN
